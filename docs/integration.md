# FormSy 集成范围与验收

本仓库提供独立的 Python 核查内核。FormSy Server 读取授权范围内的材料、固定输入并调用内核；FormSy Web 在任务的验证阶段展示候选结果。现有 TaskCheck 和 Finish Gate 保持其人工检查语义。

## 数据流

1. 用户打开任务验证页，核对绑定的会话与轮次及本次 SOP 版本。
2. 用户显式发起核查。页面说明选中材料将发送到 DeepSeek。
3. Server 用现有项目和任务权限读取确切 SOP 版本及完整来源，不借用其他身份或项目的资格。
4. Server 冻结任务、来源范围、原始 SOP bundle、证据定位及摘要，向固定的 worker 进程传入 JSON。
5. worker 使用冻结的参考条件和映射，生成语义候选，再验证条件集合、逐条引用和证据门槛。
6. Server 追加保存输入快照与结果；Web 展示候选、分析失败、未核查及未覆盖范围。
7. 用户复核后可沿用已有界面记录检查结果。新材料或新版本重新发起核查，旧报告保留。

候选报告不是执行前已遵循该规范的证明。首版按用户选择的规范回溯核查；执行前 SOP 读取事件与该任务的可靠绑定仍需单独完成。

## 首版边界

- 一个任务及其显式绑定来源；四个关联参考条件；不宣称覆盖全部六章或 33 条规则、144 个条件。
- 映射属于待复核的局部参考关系，不能自动增加任务义务。
- 普通测试输出和作者陈述不等同于可信的目标版本执行回执。未接通证据适配的运行条件保留未核查。
- worker 不执行业务代码、不修复仓库、不更改 SOP、不写人工检查、不自动完成任务。
- 报告不可变；当前检查状态与审计历史是不同记录。
- 真实材料、密钥及既有私人审计历史不进入新代码仓库。

## 最小验收

| 场景 | 应有结果 |
| --- | --- |
| 合法来源与逐字引用 | 可定位回原消息或工具调用，候选标签与验证后标签分别保存 |
| 不存在的证据 ID 或伪造引文 | 拒绝该证据，不能判通过 |
| 缺证据、缺目标版本、运行来源未核验 | 保留未核查及具体缺口 |
| 已确认失败与其他未知并存 | 失败不得被未知掩盖 |
| 长工具输出 | 完整读取或明确拒绝；不能静默折叠后审计 |
| SOP 更新或任务范围改变 | 新建报告；旧输入与结论保留 |
| 模型错误或超时 | 显示分析失败，不能显示核查通过 |
| 无项目权限或不能编辑任务 | 拒绝触发，不能跨项目读取报告 |
| 生成候选报告 | TaskCheck、知识启用状态与任务完成状态不被改变 |

离线契约测试、模拟模型集成、真实模型核查、人工认可和生产部署分别记录，不能互相替代。
