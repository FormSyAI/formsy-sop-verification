# 安全自检规则 SEC01–SEC12｜补充 0.1

日期：2026-10-08；状态：通用设计规则草案。检查对象是**具体项目的当前安全设计或实际试验**；规则列出不是检查已执行。配套：[安全专项 SOP](<安全专项SOP.md>)、[填写模板](<安全设计模板.md>)。

## 1. 判定口径

开始本轮前固定项目、有效需求/决定、对象与自身版本、平台/构建/配置、资料快照、规则版本、适用范围及所需层次。未知不自动允许；缺资料、未实现、未执行和缺环境不能改为不适用。未存在的能力才可写明范围与理由后不适用。

每个“规则×真实对象×所需层次”分开记录满足/不满足/未核查/不适用＋理由，保留依据与定位。L1 为结构核查；L2 为语义复核；L3 为实际试验。模型走读注明模型及工具，不记作真人操作。设计满足、当前环境运行、用户确认和残余风险接受并列呈现。

规则 ID 为本项目自有编号。在 `sop-module-handoff-0.2` 的 `checks.rule_id` 写 `CUSTOM:SEC01` 至 `CUSTOM:SEC12`；控制对象使用 CTRL-*，不要借规则编号替代真实对象 ID。`object_revision` 对应被检查对象自己的版本，包括来源、接口或控制，不能批量填模块文档版本。对象须声明或作为明确缺口登记；命中 CUSTOM 不表示脚本能够判定安全语义。

“L3要求”只是需要实际证明时的证据设计。文档形成阶段可先检L1/L2并保留L3待执行；进入对应实际任务前必须满足事先约定的必要证据与有效确认。不得检查失败后降低所需层次。

## 4. 报告、量化与关闭

报告至少保留：固定对象/规则/分母、各层结果、不适用理由、实际通过/失败/未执行/未验证、平台缺口、失败证据、未解决/重开问题、残余风险与有效决定、当前确认、预算与下一动作。

可以按固定集合另报：

- 设计覆盖：适用控制中，其责任、前置/拒绝结果、正常/负例断言及证据计划经复核完整的控制数 / 同一固定适用控制总数。尚未固定真实对象时不计算百分比。
- 实际通过：当前对象/构建/配置/平台下真实通过的必需用例数 / 同一固定应执行用例总数；失败、未执行和缺环境未验证均保留分母，同时列已执行数与失败数。不要拿“已执行用例通过率”充当完整覆盖。
- 关键问题：分别列当前阻塞与关闭/重开数量、理由和证据；高平均分不抵消关键越权、泄漏或证据不足。

这些是量化口径，不是本轮成绩或用户已确认门槛。单一总分不宣称安全；未固定真实对象/构建的模板不打应用分。

关闭对应原问题：文档缺卡/版本错误经当前L1/L2复检可关闭；真实失效/泄漏或关键措施未证明必须取得要求的L3证据；实质方案/权限改变先有相应有效决定与阶段确认。新增反例、组件/配置/来源变更触发影响分析与重检。取消/完成本轮、补好计划或付费额度到达不自动关闭问题。

规则全部由本项目定义，不等同 OWASP/NIST 认证控制。外部材料和原技术/知识库规则的关系见 [整合说明](<整合说明.md>)。
