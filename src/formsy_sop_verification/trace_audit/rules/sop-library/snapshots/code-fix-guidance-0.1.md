# 代码修复任务审计规则 0.1

日期：2026-10-09；状态：**设计补充，待项目采用**。用于从对话、Trace 与关联 Commit 审查代码修复任务。沿用 SOP 0.2 的 TC02、TC13、TC15 及 TC01、TC14；新增编号为 `CUSTOM:FIX01`–`CUSTOM:FIX06`，不改变原 TC 含义或计分口径。来源、冻结副本及修改对照见[参考资料](参考资料/来源与对照.md)。

## 1. 审计对象与流程

**以任务／原问题为主对象，以 Commit 链为证据。** 先固定用户明确要求、有效确认方案及其版本，再重建“原问题 → 期望行为 → 允许改动 → 验收条件”；AI 推测单列候选，不自动变为需求。标题和 Session 关联仅用于定位，多目标会话拆成任务，一个 Commit 可关联多个任务。

材料至少登记对话原文、提交 SHA／父提交／比较基准及 diff；所需源码上下文、测试日志和交付环境缺失时登记缺口，继续可独立完成的检查。逐任务关联提交，再按下表选适用检查、定位证据、形成建议并复核。合并注明所选父提交；导入或重复补丁保留关系，不能算作多次独立验证。

## 2. 六项检查

| 检查 ID／对应 SOP | 必须回答的问题 | 判断与复检要求 |
| --- | --- | --- |
| **CUSTOM:FIX01 任务与基线**／TC01、14 | 原问题、期望结果、范围、约束和目标版本来自哪里？方案是否有效确认？ | 要求与推测分开；关键未知列出查证或待决定项。记录本次采用的是历史有效标准还是回溯参考，不用新规则追认历史违规。 |
| **CUSTOM:FIX02 需求与改动对应**／TC02 | 每项要求能否对应到设计／任务、实际补丁与验收？每处实质改动是否有需求或交付目的？ | 按任务汇总提交，核对双向关联和遗漏；无明确来源的改动列待确认。有关联不等于已实现或已验收。 |
| **CUSTOM:FIX03 原问题与实际修复**／按对象选 TC04、05、06、07、09、11 | 修改触及原问题的原因吗？是否改变错误、数据、状态、权限或兼容契约？是否存在直接反例？ | 对照修改前后源码及必要上下文，按风险选失败、重复、取消、并发、恢复等边界；不强套全部场景。区分已证实缺陷与待验证风险，不以绕过校验或削弱断言冒充修复；必须实测的行为保留运行核验。 |
| **CUSTOM:FIX04 验证内容**／TC13，验收设计按需用 TC12 | 用例是否触发原问题、断言期望行为并覆盖关键反例？前置状态和输入是否有效？ | 审查断言而非文件存在或测试数量。定位适用要求与用例的缺口；承诺 TDD 时核红绿顺序，不对全部历史任务补加 TDD 要求。局部用例满足不能代表整项 TC13 满足。 |
| **CUSTOM:FIX05 实际运行与交付**／TC01、14及真实验收要求 | 哪个版本、环境、数据实际运行了哪些操作和断言？结果能否支持完成声明？ | 作者声明、工具原始输出和审计者实测分别登记；测试代码与运行结果分开。模拟／真实、局部／全量、工作区／交付构建分别判断；旧版本证据复用须评估影响，不能直接继承通过。 |
| **CUSTOM:FIX06 修订、复检与关闭**／TC15 | 原失败、修订及影响范围是否保留？针对问题和受影响路径复检了吗？剩余验收怎样处理？ | 关闭须有对应版本的有效复检及所需验收依据；无发现也留复核记录。受阻、暂停或取消不计关闭；新反例或版本变化触发重开／失效评估。 |

## 3. 判定与证据边界

每项先记适用性：**适用／不适用／待确认**；再按原 SOP 四态记录：**满足／不满足／未核查／不适用＋理由**。满足须覆盖声明范围及所需层次；不满足须有直接证据证明适用条件未满足，如行为反例或已核实的必需关联遗漏；证据不足、未查完或适用性待确认记未核查。缺材料、缺环境、未执行不能记不适用；缺日志不能推断没执行，作者声称通过不能代替核验。

L1 字段与引用、L2 内容判断、必要 L3 实际核验分别记录。源码和有效资料足以回答的事实不强制重跑；依赖目标环境的验收不能省略运行证据。**测试设计满足、实际运行通过、任务具备关闭依据分别报告**，不以局部通过推出整体完成，不按 Commit 数或规则行数计算质量分。

## 4. 最小产出与复核

每个任务输出：**需求与版本 → 实际行为／改动 → 规则、适用性、层次和范围 → 四态结论与证据定位 → 缺口／影响 → 改进建议 → 复检操作与预期断言 → 复核人及状态**。证据绑定文件行／日志事件／消息定位及版本；原文、转述、推断分开，敏感内容脱敏。缺陷候选与证据缺口分别列出，给出可执行的补证或验证条件，不能只写“加强测试”。

模型辅助拆任务、匹配证据和提出候选；程序校验字段、引用、版本与范围，不能证明语义正确或证据真实。独立审阅者复核关键结论及关闭依据；尚未复核标明候选。首轮用少量真实样本验证建议是否准确、可用，不将模型自评分当作效果。

例：`9b3422e0` 的已见差异支持“先进入 Git 流再检查中止”的局部测试设计判断；原始运行日志未取得，完整过期错误断言仍需上下文核对，不能推出实际复检通过或真实 GitHub App 交付完成。详见[例子与来源边界](参考资料/来源与对照.md#3-试用例与证据边界)。
